How the internet works

One message.
Across the world.

Follow a single message from your laptop to a server in another country, and back, in less time than a blink. Scroll to travel with it.

A simulation. Every address and time on this page is an example, and nothing about you is collected.

tcpdump -n · en0 (simulated)


          

        

        
    
          
  1. 
            
    Stop 1 · Inside your laptop
    
            
    It starts inside your laptop.
    
            
    Before anything leaves, it's packed in layers. The application, your browser, writes the message as an HTTPS request, encrypted so only the server can read it.
    
          
    2. 
          
  2. The transport layer, TCP, first shakes hands with the server (SYN, SYN-ACK, ACK), then numbers the pieces so they can be put back in order.
    3. 
          
  3. The internet layer, IP, adds where it's from and where it's going, like an address on an envelope.
    4. 
          
  4. The link layer wraps it for Wi-Fi, and it leaves as radio waves: ones and zeros.
    5. 
        

      

    


    
    

      

        

          
        

        
    
          
  1. 
            
    Stop 2 · Your home
    
            
    Then it crosses your home.
    
            
    Your laptop has a private address, 192.168.1.23. Only your home network knows it.
    
          
    2. 
          
  2. It sends the message over Wi-Fi to your router, the gateway between your home and the internet.
    3. 
          
  3. The router swaps your private address for its public one, 203.0.113.45, and remembers the swap so replies find you. This is called NAT.
    4. 
          
  4. Then it leaves along the line to your internet provider.
    5.

  1. 
              
    Stop 3 · Across the internet
    
              
    Hop by hop to the server.
    
              
    First, DNS turns the name example.com into a number the network understands: 198.51.100.24.
    
            
    2. 
            
  2. Each router reads the address and passes the packet one hop closer. Each one also lowers its TTL by one, so a lost packet can't loop for ever.
    3. 
            
  3. At an internet exchange, different networks hand traffic to each other. Long distances cross on fibre-optic cables, some laid under oceans.
    4. 
            
  4. The server receives it after 5 routers, 6 hops in all. Its reply makes the same kind of trip back.
    5. 
          

        

      

    


    
    

      

        

          
Why it matters

          
What this means for scams.

        

        
    
          
  • The padlockEncrypted isn't honest.HTTPS means nobody can read the message on its way. It says nothing about who's on the other end: scam sites have padlocks too.
    • 
          
  • The nameYou only see the name.DNS hides the numbers behind web addresses, so a lookalike name is all a scammer needs. Read the name just before the first single slash.
    • 
          
  • The routerNAT isn't a shield.Your router hides your devices' private addresses, but it can't stop you being tricked, and it needs updates like everything else.
    • 
          
  • LiveSee real attacks →Threat Watch shows where attacks on websites came from this week.
    • 
        

        
Example addresses come from ranges reserved for examples: 192.168.x.x is private (RFC 1918), and 203.0.113.0/24 and 198.51.100.0/24 are for documentation (RFC 5737). Times and hop counts are typical, not measured.
